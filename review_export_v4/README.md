# 대구상공회의소 교육센터 홈페이지 (코드 검토용본 v4 - 최종 검증판)

V3의 치명적인 오류와 누락된 코드를 모두 복원하고, 완벽한 보안과 무결성을 보장하는 V4 아키텍처입니다.

## 📁 주요 수정 및 복원 내용 (V4)

### 1. 누락된 기존 로직 완벽 복원 (`proxy.js`)
- 생략되었던 `GET` 요청의 데이터 변환 맵핑(`cost`, `paymentInfo` 파싱 등)과 `add_course`, `update_course`, `delete_course` 코드를 모두 기존 작동 방식 그대로 완벽하게 복원했습니다. 기존의 프론트엔드 연동에 전혀 문제가 없습니다.

### 2. 관리자 인증(RBAC) 기준 통일 및 보안 강화
- **서버 검증 (`proxy.js`):** JWT의 `user.app_metadata.role === 'admin'` 조건을 엄격하게 검사하여 관리자가 아니면 차단합니다.
- **SQL 검증 (`01_setup.sql`):** RLS 정책에서도 `auth.jwt() -> 'app_metadata' ->> 'role' = 'admin'`을 사용하여 서버와 데이터베이스의 판단 기준을 완벽하게 통일했습니다.
- **기존 정책 파기:** `DROP POLICY IF EXISTS`를 명시하여 기존의 느슨한 정책을 파기하고 강력한 `WITH CHECK(false)` 정책으로 덮어씁니다.

### 3. 익명(anon) 사용자 보안 및 서비스 롤(Service Role) 도입
- 교육 신청(익명) 시, RLS에 막혀 `sync_status`(연동 실패/성공 여부) 업데이트가 불가능했던 문제를 해결했습니다.
- 관리자 권한 키(`SUPABASE_SERVICE_ROLE_KEY`)를 사용하여, 익명 사용자의 신청 과정에서도 DB에 구글 시트 연동 실패 여부를 100% 안전하게 기록하고 관리자만 재처리할 수 있도록 격리했습니다.

### 4. 멱등성 보장 방식을 업무 기준에서 "요청 식별자" 기준으로 변경
- 같은 회사 직원이 동일한 회사 이메일로 각각 신청하면 중복으로 튕기던 V3의 치명적 결함을 수정했습니다.
- 프론트엔드(`index.html`)에서 폼을 열 때마다 고유한 `req_id`를 발급하여 전송합니다. 사용자가 '새로고침'이나 '더블 클릭'을 할 때만 차단(`UNIQUE(req_id)`)되며 정상적인 동료의 신청은 막지 않습니다.

### 5. 구글 Apps Script 보안 및 시트 타겟팅 고도화
- 열려있는 아무 시트(Active)나 건드리지 않고, 명확하게 `SPREADSHEET_ID`와 시트 탭 이름(`SHEET_NAME`)을 고정하여 다른 시트가 열려 있어도 안전합니다.
- `API_SECRET` 인증 키를 도입하여 누군가 악의적으로 주소만 알아내어 가짜 데이터를 꽂아 넣는 해킹을 원천 차단했습니다.
- 덮어쓰기(Upsert) 과정에서 직원이 입력한 '입금 여부', '메모' 열은 절대 건드리지 않도록 배열 인덱스를 명확히 격리했습니다.

### 6. 검증 스크립트 수정 및 확실한 성공/실패 판정
- `tests/test_mock.js`와 `test_results.txt`를 통해 성공과 실패(정원 초과, 중복 방지 제약조건 발동)에 대한 예상 값과 실제 값을 명확히 분리하여 기술했습니다.

## 🚀 배포 및 적용 가이드

본 검토용 폴더(`review_export_v4`)의 코드를 실제 운영 서버에 반영하려면 다음 순서를 따라주세요.

1. **Vercel 환경 변수 세팅:** `SUPABASE_SERVICE_ROLE_KEY` 와 `APPS_SCRIPT_SECRET` 환경 변수를 Vercel 대시보드에 추가합니다.
2. **Supabase SQL 실행:** `sql/01_setup.sql` 을 복사하여 Supabase SQL Editor에서 실행합니다. (기존 정책 삭제 -> 컬럼 추가 -> RLS 재설정 -> RPC 생성)
3. **구글 시트 스크립트 배포:** `scripts/google_apps_script.js` 코드를 구글 스프레드시트의 Apps Script 편집기에 붙여넣고 상단의 변수(시트 아이디, 시트명, 시크릿 키)를 설정한 후 웹 앱으로 **'새 버전 배포'** 합니다.
4. **Vercel 운영 코드 배포:** `public/index.html`, `public/admin.html`, `api/proxy.js` 코드를 운영 GitHub 브랜치에 Push 하여 배포를 완료합니다.
